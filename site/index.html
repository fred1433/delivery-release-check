    How a verdict is made

    The rules are plain code, written from Shipping Information and the product pages. A model did one job, once, when this page was built: read each fictional customer message and return facts with the exact words they came from. The code throws away any fact whose words are not in the message, any width without a unit, and any extraction made from a different version of the message. A quote proves where a fact came from, not that it was read right, so the repository tests negations, corrections and conflicting messages.

    Where it would run

    A HOLD written to monday.com is a warning, not a lock. In production the check would sit on the route that actually releases a shipment. Shopify's fulfillmentOrderReleaseHold releases every hold when holdIds is left out, so the code refuses any release that does not name the holds it owns. Duplicates are caught on the webhook id and recorded in a durable action log, because monday.com's idempotency cache lasts 30 minutes. The repository has the n8n workflow, run on a clean n8n 2.41 with these same orders, and 56 tests.

    What it does not do

    It schedules nothing, contacts no one and changes nothing in Shopify, Gorgias or monday.com. Your team keeps every decision on customers, dates and the warehouse. When two of your pages differ, it records both and names who has to decide; it does not pick a side. The order structure is illustrative: how your add-ons and payments are really recorded has not been checked.
